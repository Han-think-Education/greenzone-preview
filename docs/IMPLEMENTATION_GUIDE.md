# 현재 구현 구조

현재는 가상 시연 대신 신월1동·화곡1동의 공식 자료를 조인한 분석 결과를 사용합니다. 실행은 [빠른 안내](../QUICK_START_KO.md), 데이터 근거는 [권역 분석](COLLECTION_TERRITORIES.md)을 따릅니다.

## 분석과 웹을 연결하는 구조

| 부분 | 담당 작업 | 현재 자료·코드 |
| --- | --- | --- |
| 별도 분석 | 경계·건물·대장·도로 조인, 용도 분류, 권역·배정·방문 순서 계산 | 상세 GreenZone 프로젝트에서 수행. 결과만 이 저장소에 포함 |
| 분석 지도 | 동 경계·용도·제안 권역·조사점·도로 시나리오 표시 | `data/pilot_analysis.json`, `preview/app.js` |
| 주소 선택 | 도로명주소·건물명 검색 → 필지 ID → 기존 배정 → 조사점 | `buildings` / `survey_assignments` / `survey_references` |
| API·DB | 카탈로그·품목·안내문·담당자 기록 | `backend/app.py`, `catalog.py`, `waste_catalog.py`, `knowledge.py` |
| 관리자 | 한 계정 로그인, 수정 충돌·이력 관리 | `backend/auth.py`, `preview/admin.js` |
| 영상 배경 | 서버에서 인증키를 사용해 VWorld 타일 연결 | `backend/map_tiles.py` |
| 선택 AI | 질문 분류, BGE-M3 문서 검색 | `backend/chat_service.py`, `knowledge.py` |

분석을 웹에서 새로 학습하거나 실시간 최적화하지 않습니다. 지도 검색은 수집 파일 내부 조회입니다. 자료가 없는 주소를 임의로 생성하지 않습니다.

## 포함한 데이터와 갱신

- 공간 분석 결과: `data/pilot_analysis.json`.
- SQLite 초기 카탈로그: `data/analysis_result.json`.
- 공식 품목·수수료: `data/waste_catalog.json`.
- 공식 문서 요약: `data/knowledge_documents.json`.
- 분석 원본·수집 스크립트·조사 대장은 상세 프로젝트가 정본이며, 팀원은 포함된 결과 파일로 웹을 실행할 수 있습니다.

분석 결과를 갱신할 때는 동일 스키마의 파일로 교체하고 자료 기준일·출처·가정·누락을 함께 기록합니다. SQLite에 이미 저장된 담당자 수정은 보존합니다. 활성 조사점 교체와 과거 조사점 보관은 `analysis_active`로 구분합니다. 관리자 좌표를 바꿔도 분석 지도·거리 지표·권역은 자동 재계산되지 않습니다. 별도 분석을 다시 수행해 결과를 반영해야 합니다.

## 실행과 저장

Docker의 `web` 컨테이너 하나가 FastAPI와 정적 화면을 제공합니다. SQLite는 별도 볼륨에 보관합니다. MariaDB나 별도 FastAPI 컨테이너는 필요 없습니다. Ollama는 선택한 외부 모델 서버이며 공유 예제 주소는 `http://host.docker.internal:11434`입니다. 직접 Python 실행은 `http://127.0.0.1:11434`를 사용합니다.

관리 기능은 12자 이상 암호가 있는 한 계정·단일 서버 프로세스를 전제로 합니다. 실제 다중 사용자·기관 운영·보안 관제는 별도 설계 대상입니다. 로컬 실행은 접속정보를 `storage`에 만들 수 있으며 이를 공유하지 않습니다.

## 구현 가이드로 확인한 범위

Docker 빌드·서버 시작과 브라우저에서 지도·영상 배경·건물명/도로명 검색·선택한 위치의 제안 배정 표시를 관찰했습니다. 품목·문서 데이터 등록과 실제 모델의 정확도 검증은 별개입니다. 이번 공유 문서 제작에서 모델 추론·재색인·자동 테스트·관리자 저장·위치 권한 요청·현장 검증은 수행하지 않았습니다.

조사점은 배출·정차 승인 장소가 아닙니다. 도로는 양방향 평면 연결 가정이며 일방통행·입체교차·차량 높이·폭·정차면은 확인 전입니다. AI가 현장 안전이나 수수료를 추정해 확정하지 않습니다.
